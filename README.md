# Toewaioo's Studio

မြန်မာနှင့် အင်္ဂလိပ်ဘာသာဖြင့် မင်္ဂလာဖိတ်စာဖန်တီးနိုင်သည့် ဝဘ်အက်ပ်နှင့် သီးခြား 3D အမှတ်တရအတွေ့အကြုံဖြစ်သည်။ ဧည့်သည်များသည် အကောင့်ဖွင့်စရာမလိုဘဲ ဖိတ်စာဖန်တီးမျှဝေနိုင်ပြီး စတူဒီယိုပိုင်ရှင်သည် သီးသန့်စီမံခန့်ခွဲမှုနေရာမှ ဖိတ်စာများနှင့် အပ်နှံသူအချက်အလက်များကို စီမံနိုင်သည်။

## အဓိကလုပ်ဆောင်ချက်များ

### မင်္ဂလာဖိတ်စာ

- Thazin၊ Golden Vow နှင့် Rose Reverie ဟူသော ဒီဇိုင်းသုံးမျိုးနှင့် အရောင်အပြင်အဆင်လေးမျိုး ရွေးချယ်နိုင်သည်။
- စာအိတ်ဖွင့်သည့် လှုပ်ရှားမှု၊ စာမျက်နှာလှန်နိုင်သော ဖိတ်စာစာအုပ်၊ ဓာတ်ပုံပြခန်းနှင့် ဖုန်း/ကွန်ပျူတာမျက်နှာပြင်အကျယ်အလိုက် ညှိထားသော ပုံစံတို့ ပါဝင်သည်။
- ပွဲရက်၊ အချိန်၊ နေရာ၊ အစီအစဉ်၊ ရက်တွက်ပြသမှုနှင့် မြေပုံလင့်ခ်တို့ကို ထည့်နိုင်သည်။
- ဧည့်သည်ဖန်တီးသော ဖိတ်စာတစ်စောင်လျှင် ဓာတ်ပုံ ၃ ပုံအထိ၊ ပိုင်ရှင်စီမံသော ဖိတ်စာတစ်စောင်လျှင် ၈ ပုံအထိ ထည့်နိုင်သည်။ JPG၊ PNG နှင့် WebP ကို လက်ခံပြီး ဓာတ်ပုံတစ်ပုံလျှင် အများဆုံး 4,490,000 bytes (ခန့်မှန်း 4.49 MB) ဖြစ်သည်။
- ဧည့်သည်ဖန်တီးမှုတွင် အကောင့်၊ မူကြမ်းသိမ်းဆည်းမှုနှင့် နောက်မှပြန်ပြင်နိုင်မှု မရှိပါ။ ထုတ်ဝေပြီးနောက် ဖိတ်စာကို ပြင်ဆင်ခြင်း သို့မဟုတ် ပြန်လည်ရယူခြင်း မပြုနိုင်ပါ။ မျှဝေလင့်ခ်ရရှိသူတိုင်းသည် ဖိတ်စာအချက်အလက်နှင့် ဓာတ်ပုံများကို ကြည့်နိုင်သဖြင့် လင့်ခ်ကို သတိထားမျှဝေပါ။
- ပိုင်ရှင်၏ မူကြမ်းများမှာ သီးသန့်ဖြစ်သည်။ ထုတ်ဝေထားသော ဖိတ်စာကို ပြင်ဆင်မီ မျှဝေမှုကို ရပ်ရမည်။ ပြင်ဆင်သိမ်းဆည်းခြင်း သို့မဟုတ် မျှဝေမှုကို ရပ်ခြင်းက လင့်ခ်အဟောင်းကို ပိတ်သည်။ ပြန်မျှဝေရန် ဖိတ်စာကို ထပ်မံထုတ်ဝေရမည်။
- ထုတ်ဝေပြီးသော ဖိတ်စာအတွက်သာ မျှဝေလင့်ခ်နှင့် နှလုံးပုံ QR ရရှိသည်။

### Love Galaxy

Love Galaxy သည် ဖိတ်စာစနစ်နှင့် သီးခြားဖြစ်သော 3D အမှတ်တရအတွေ့အကြုံဖြစ်သည်။ ဓာတ်ပုံလေးပုံ၊ ကိုယ်ပိုင်တေးသံနှင့် စိတ်ကြိုက်စာသားများဖြင့် ဖန်တီးနိုင်ပြီး မျှဝေလင့်ခ်နှင့် QR ရရှိနိုင်သည်။ အခြားသူများ၏ အမှတ်တရကမ္ဘာများကို မျှဝေခရီးတွင် ဖော်ပြရန် ပိုင်ရှင်ကိုယ်တိုင် သဘောတူထားမှသာ ခွင့်ပြုသည်။ ပုံမှန် `production` build တွင် မျှဝေခရီးလုပ်ဆောင်ချက်ကို ပိတ်ထားပြီး Vercel `preview` build တွင်သာ သီးခြားဖွင့်ထားသည်။

## နည်းပညာနှင့် လုံခြုံရေး

React၊ TypeScript၊ Bun၊ Vite၊ Vercel Functions နှင့် Supabase ကို အသုံးပြုထားသည်။ Supabase Auth သည် ပိုင်ရှင်ဝင်ရောက်မှုကို ကိုင်တွယ်ပြီး PostgreSQL Row Level Security (RLS) သည် ဒေတာပိုင်ဆိုင်မှုနှင့် ဝင်ရောက်ခွင့်ကို ကာကွယ်ပေးသည်။

Browser သည် Supabase Auth၊ REST၊ RPC သို့မဟုတ် Storage သို့ တိုက်ရိုက်မချိတ်ဆက်ပါ။ တောင်းဆိုချက်များသည် တူညီသောဒိုမိန်းရှိ `/api/...` ဆာဗာလုပ်ဆောင်ချက်များမှတစ်ဆင့်သာ ဖြတ်သန်းသည်။ ပိုင်ရှင်၏ ဝင်ရောက်ခွင့်တိုကင်များကို `HttpOnly` cookie ထဲတွင် သိမ်းဆည်းပြီး browser JavaScript သို့ မပေးပို့ပါ။ ဓာတ်ပုံသိုလှောင်ရာမှာ သီးသန့်ဖြစ်သည်။ `service_role` key ကို လိုအပ်သော Supabase Edge Functions များ၏ ဆာဗာဘက်တွင်သာ အသုံးပြုသည်။

အများပြည်သူကြည့်ရှုနိုင်သော ဖိတ်စာတွင် အသုံးပြုသူ၏ အီးမေးလ်၊ ဖုန်းနံပါတ်နှင့် သီးသန့်မှတ်စုများကို မပြပါ။ သို့သော် မျှဝေလင့်ခ်ရရှိသူတိုင်းသည် ဖိတ်စာအတွက် ထုတ်ဝေထားသော အချက်အလက်နှင့် ဓာတ်ပုံများကို ကြည့်နိုင်သည်။ လင့်ခ်ကို ပိတ်လိုက်သော်လည်း အခြားသူများ ကြိုတင်သိမ်းဆည်းထားသည့် မိတ္တူ၊ ဓာတ်ပုံ သို့မဟုတ် ဖန်သားပြင်ပုံများကို ပြန်ဖျက်၍မရပါ။

## ကွန်ပျူတာပေါ်တွင် စတင်အသုံးပြုခြင်း

လိုအပ်သည်များမှာ Bun နှင့် Git ဖြစ်သည်။

```bash
bun install
cp .env.example .env.local
```

အသုံးပြုသူမျက်နှာပြင်နှင့် စမ်းသပ်မုဒ်ကိုသာ ဖွင့်ရန် `.env.local` ထဲတွင် `VITE_LOCAL_DEMO=true` ဟု သတ်မှတ်ပြီး အောက်ပါအတိုင်း လုပ်ဆောင်ပါ။

```bash
bun run dev
```

စာမျက်နှာကို `http://localhost:5173` တွင် ဖွင့်နိုင်သည်။ စမ်းသပ်မုဒ်၏ ဒေတာများကို ထို browser ထဲတွင်သာ သိမ်းဆည်းပြီး အခြားစက်များနှင့် ထပ်တူပြုမည်မဟုတ်ပါ။ ၎င်းသည် အမှန်တကယ် မျှဝေလင့်ခ်ဝန်ဆောင်မှု မဟုတ်ပါ။ Supabase အစစ်အမှန်ကို ချိတ်ဆက်အသုံးပြုရန် အောက်ပါ ဆာဗာသတ်မှတ်ချက်များကို ဖြည့်ပြီး `VITE_LOCAL_DEMO` ကို `false` ဟု သတ်မှတ်ပါ သို့မဟုတ် မထည့်ပါနှင့်။

### အသုံးများသော command များ

```bash
bun run dev        # စမ်းသပ်ရေးဆာဗာ
bun run typecheck  # TypeScript စစ်ဆေးရန်
bun run test       # စမ်းသပ်မှုများ လုပ်ဆောင်ရန်
bun run build      # အများသုံးဗားရှင်း တည်ဆောက်ရန်
bun run preview    # တည်ဆောက်ထားသောဗားရှင်းကို ကြိုတင်ကြည့်ရန်
```

`bun run test` သည် project ၏ `.env.local` သတ်မှတ်ချက်များကို စမ်းသပ်မှုအတွင်း မသုံးဘဲ လုပ်ဆောင်ရန် ပြင်ဆင်ထားသည်။ ဒေတာဘေ့စ်စမ်းသပ်မှုများက local PGlite ကို သုံးသည်။ ၎င်းတို့သည် live Supabase login၊ အမှန်တကယ်စက်ပစ္စည်း သို့မဟုတ် production E2E စမ်းသပ်မှုအပြည့်ကို အစားမထိုးပါ။

## ပတ်ဝန်းကျင်ဆိုင်ရာ ပြင်ဆင်မှုများ

`.env.example` ကို နမူနာအဖြစ် အသုံးပြုပါ။ `.env.local` နှင့် သော့များပါဝင်သော ဖိုင်များကို Git တွင် မထည့်သွင်းပါနှင့်။ ဆာဗာအတွက် သတ်မှတ်ထားသော တန်ဖိုးများရှေ့တွင် `VITE_` ရှေ့ဆက်စာလုံး မထည့်ပါနှင့်။ ထိုရှေ့ဆက်စာလုံးပါသော ပြင်ဆင်မှုများသည် ဘရောက်ဇာ bundle ထဲသို့ ပါဝင်သွားနိုင်သည်။

### Vercel ဆာဗာ ပြင်ဆင်မှု

| ပြင်ဆင်မှု | ရည်ရွယ်ချက် |
| --- | --- |
| `SUPABASE_URL` | Supabase ပရောဂျက်၏ URL |
| `SUPABASE_ANON_KEY` | Supabase ၏ အများသုံးသော့။ ဆာဗာတောင်းဆိုမှုများတွင် အသုံးပြုသည် |
| `STUDIO_ADMIN_USER_ID` | စနစ်စီမံခန့်ခွဲမှုသို့ ဝင်ရောက်ခွင့်ရှိသော Auth အသုံးပြုသူ၏ UUID။ ဗလာဖြစ်ပါက စီမံခန့်ခွဲမှုကို ပိတ်ထားသည် |
| `APP_ORIGIN` | အက်ပ်၏ အဓိက HTTPS လိပ်စာ။ Supabase တွင် ခွင့်ပြုထားသော လိပ်စာနှင့် ကိုက်ညီရမည် |
| `GUEST_UPLOAD_BRIDGE_SECRET` | ဧည့်သည်ဓာတ်ပုံများနှင့် Love Galaxy တောင်းဆိုမှုများကို ကာကွယ်သည့် လျှို့ဝှက်တန်ဖိုး။ Supabase Edge ပြင်ဆင်မှုတွင် တူညီသောတန်ဖိုးကို အသုံးပြုရမည် |
| `VITE_LOCAL_DEMO` | ဒေသတွင်း ဘရောက်ဇာ စမ်းသပ်မှုအတွက်သာ `true` ထားပါ။ အများပြည်သူသုံး ပတ်ဝန်းကျင်တွင် မဖွင့်ပါနှင့် |

Vercel ဘက်တွင် `SUPABASE_SERVICE_ROLE_KEY` မလိုအပ်ပါ။ ဤသော့ကို Vercel ၏ ဘရောက်ဇာ ပြင်ဆင်မှုများ သို့မဟုတ် `VITE_` ပြောင်းလဲနိုင်သောများထဲသို့ မထည့်ပါနှင့်။

### Supabase Edge Function လျှို့ဝှက်တန်ဖိုးများ

Edge Function ပတ်ဝန်းကျင်တွင် `SUPABASE_URL`၊ `SUPABASE_SERVICE_ROLE_KEY`၊ `GUEST_UPLOAD_BRIDGE_SECRET`၊ `ALLOWED_ORIGINS` နှင့် `IP_HASH_SALT` တို့ကို ပြင်ဆင်ပါ။ `ALLOWED_ORIGINS` တွင် အက်ပ်၏ အပြည့်အစုံသော လိပ်စာများကို စာရင်းပြုစုပါ။ `GUEST_UPLOAD_BRIDGE_SECRET` ကို Vercel တွင် ပြင်ဆင်ထားသော တန်ဖိုးနှင့် အတိအကျ တူညီစွာထားပါ။ ဤလျှို့ဝှက်တန်ဖိုးများကို မူရင်းကုဒ်၊ README သို့မဟုတ် ဘရောက်ဇာ ပြင်ဆင်မှုများတွင် မထည့်ပါနှင့်။

## Supabase နှင့် အများပြည်သူထံ ဖြန့်ချိခြင်း

1. Supabase ပရောဂျက်၏ migration မှတ်တမ်းနှင့် ဒေတာအရန်သိမ်းဆည်းမှုကို ဦးစွာ စစ်ဆေးပါ။ အသစ်စက်စက် ဒေတာဘေ့စ်တွင် `supabase/migrations/` အတွင်းရှိ ပြောင်းလဲမှုများကို ရက်စွဲနှင့် အမည်အစီအစဉ်အတိုင်း အသုံးချပါ။ ရှိပြီးသား ပရောဂျက်တွင် မှတ်တမ်းကို မစစ်ဆေးဘဲ migration ကို ထပ်မံအသုံးချခြင်း သို့မဟုတ် အမှန်တကယ်ဒေတာကို ပြောင်းလဲခြင်း မပြုပါနှင့်။
2. `supabase/functions/` အတွင်းရှိ `guest-invitation`၊ `guest-upload`၊ `invitation-photo` နှင့် `love-galaxy` လုပ်ဆောင်ချက်များကို ပြင်ဆင်ထားသော Supabase ပရောဂျက်သို့ ဖြန့်ချိပါ။ JWT အတည်ပြုမှု ပြင်ဆင်ချက်သည် `supabase/config.toml` နှင့် လုပ်ဆောင်ချက်တစ်ခုချင်းစီ၏ ဝင်ရောက်ခွင့်ပုံစံနှင့် ကိုက်ညီရမည်။
3. Vercel ပရောဂျက်၏ ဆာဗာပြင်ဆင်မှုများကို အမှန်တကယ် ပတ်ဝန်းကျင်နှင့် လိုအပ်ပါက အကြိုကြည့်ရှုမှု ပတ်ဝန်းကျင်များတွင် ထည့်သွင်းပါ။ `vercel.json` သည် `/api` လမ်းကြောင်းကို SPA လမ်းညွှန်ပြောင်းလဲမှုမှ သီးခြားထားပြီး API လုပ်ဆောင်ချက်များကို ဆက်လက်ပေးပို့စေသည်။
4. Supabase Auth ၏ ခွင့်ပြုထားသော ဒိုမိန်း၊ ပြန်လည်လမ်းညွှန်မည့် URL နှင့် Edge Function ၏ ခွင့်ပြုထားသော လိပ်စာများကို Vercel ၏ အမှန်တကယ် ဒိုမိန်းနှင့် ကိုက်ညီအောင် ပြင်ဆင်ပါ။
5. အများပြည်သူထံ ဖြန့်ချိပြီးနောက် ပိုင်ရှင်ဝင်ရောက်မှု၊ ဧည့်သည်ဖိတ်ကြားချက် ဖန်တီးမှု၊ ဓာတ်ပုံကြည့်ရှုခွင့်၊ လင့်ခ်ပယ်ဖျက်မှု၊ ပြန်လည်ဝင်ရောက်မှုနှင့် မျှဝေလင့်ခ်/QR ကို အမှန်တကယ် စက်ပစ္စည်းဖြင့် စစ်ဆေးပါ။

`dist/` အတွင်းရှိ အငြိမ်ဖိုင်များကို သီးခြားဖြန့်ချိပါက တိမ်တိုက်ဝန်ဆောင်မှုလုပ်ဆောင်ချက်များ အလုပ်လုပ်မည်မဟုတ်ပါ။ Vercel ဖြန့်ချိမှုသည် `api/` အတွင်းရှိ ဆာဗာလုပ်ဆောင်ချက်များနှင့် SPA လမ်းညွှန်ပြောင်းလဲမှုကို အတူတကွ အသုံးပြုသည်။ `vercel.json` တွင် ယာယီသိမ်းထားသော ဧည့်သည်ဓာတ်ပုံများနှင့် Love Galaxy တင်ပို့ထားသော ဒေတာများကို နေ့စဉ်ရှင်းလင်းရန် `cron` အလုပ်များကိုလည်း သတ်မှတ်ထားသည်။

## ဒေတာရွှေ့ပြောင်းခြင်း

`scripts/migrate-sqlite.ts` သည် SQLite ဒေတာဟောင်းများကို အလုပ်နေရာတစ်ခုချင်းစီအလိုက် စစ်ဆေးပြီး ရွှေ့ပြောင်းရန် အသုံးပြုသော အကူကိရိယာဖြစ်သည်။ မူလလုပ်ဆောင်မှုမှာ dry-run ဖြစ်ပြီး ကြိုတင်စစ်ဆေးရုံသာ ပြုလုပ်ကာ ဒေတာရေးသားမည်မဟုတ်ပါ။ အမှန်တကယ် ရွှေ့ပြောင်းရန် `--apply`၊ ရှိပြီးသားပိုင်ရှင်၏ UUID နှင့် ဆာဗာဘက်ရှိ `SUPABASE_SERVICE_ROLE_KEY` လိုအပ်သည်။ တင်သွင်းထားသော ဖိတ်ကြားချက်များသည် ကိုယ်ပိုင်မူကြမ်းအဖြစ်သာ ဝင်လာပြီး မျှဝေလင့်ခ်ဟောင်းများကို မယူဆောင်လာပါ။ ဒေတာအရန်သိမ်းဆည်းမှုနှင့် ပိုင်ရှင်၏ ခွင့်ပြုချက်မရှိဘဲ မလုပ်ဆောင်ပါနှင့်။
